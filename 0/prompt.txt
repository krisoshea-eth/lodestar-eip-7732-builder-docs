## Settled architecture and protocol decisions

- Builder deposit request type is `0x03`; Builder withdrawal credentials use prefix `0xB0`. Devnet-7 uses deposit contract `0x0000bff46984e3725691fa540a8c7589300d8282` and exit contract `0x000064d678505ad48f8ccb093bc65613800e8282`.
- Builder lifecycle currently includes a 64-request deposit cap, 64-epoch minimum withdrawability delay, payload-builder eligibility, and a system-call contract-disable path with reduced throughput limits.
- `PAYLOAD_DUE_BPS=5000`, placing the payload-availability deadline six seconds into a 12-second slot.
- [Consensus #5497](https://github.com/ethereum/consensus-specs/pull/5497) admits and propagates multiple bids compatible with the node's local head view, including relevant FULL/EMPTY paths; incompatible-branch bids are ignored.
- [Consensus #5473](https://github.com/ethereum/consensus-specs/pull/5473) looks up payload availability at the parent block slot, preventing skipped-slot timely-head errors.
- [Consensus #5495](https://github.com/ethereum/consensus-specs/pull/5495) returns early for an already-known block, preserving PTC votes and timeliness state on redelivery.
- Proposer-preference APIs are merged; invalid preferences are ignored. Dependent-root age/boundary-child rules are settled upstream and implemented by Lodestar [#9695](https://github.com/ChainSafe/lodestar/pull/9695).
- One signed execution payload envelope supports stateful and stateless publication shapes via `Eth-Blob-Data-Included`; `consensus_and_equivocation` remains the Builder-facing validation target.
- `head_v2` EMPTY→FULL second emission is a SHOULD; other FULL/EMPTY edge emissions remain implementation-specific.
- ProduceBlockV4 carries execution value for multi-beacon-node selection. Local building remains the floor, local wins ties, and remote policy uses matched/unmatched preference rules in the still-open API work.
- Lodestar forwards a bid only when it exceeds the tuple's high bid by `min(max(0.0001 ETH, 3%), 0.01 ETH)`; local acceptance and gossip forwarding are intentionally distinct.
- Bid fields that contribute to SSZ roots must remain exact `uint64` values through parsing, caching, signing, hashing, proposer preferences, `PayloadAttributesV4`, and events. Lodestar [#9749](https://github.com/ChainSafe/lodestar/pull/9749), [#9750](https://github.com/ChainSafe/lodestar/pull/9750), and [#9751](https://github.com/ChainSafe/lodestar/pull/9751) implement this on unstable; JavaScript `number` is unsafe for unbounded values above `2^53`.

- Test local EL connection refusal, timeout, pruning, syncing, invalid payload, malformed peer response, and mid-stream reorg separately. Assert only peer-attributable failures affect peer scores.
- For skipped slots, query parent payload availability using the parent block slot. For FULL parents, select operations and compute rewards from the payload-applied state while preserving original parent state where the transition requires it.

- Builder API integration tests must cover signed auth, mandatory headers, timeout propagation, batched preferences, local tie wins, matched/unmatched remote bids, maximum payment policy, signed bid wrappers, winning-Builder URL round trip, and stateful/stateless production.
