# ENV-02 first-machine evidence - 31 August 2026

## Verdict

The pinned ENV-02 fixture passed on the first development machine. Three clean Kurtosis launches succeeded. The runs proved API-02's real BN event-to-block path, retained-root duplicate suppression, and graceful shutdown both with a connected SSE stream and after that stream was interrupted.

This is point-in-time local evidence. It does not establish continuous devnet health, Builder selection, payload reveal, or recovery across replay and restart. ENV-02 remains open until a second contributor reproduces the run from the stored fixture and runbook.

## Results

### Event-to-block path

The recording proxy captured one `GET /eth/v1/events?topics=block` subscription. Each imported post-Gloas block event caused a root-addressed `GET /eth/v2/beacon/blocks/{root}` request, followed by one `Observed post-Gloas block` log with the same slot and root.

The observed blocks in this minimal one-participant setup were self-builds. `builderIndex=Infinity` passed through unchanged, as required. This run does not claim an external Builder selection or payload reveal.

### Duplicate suppression

With `DUPLICATE_FIRST_BLOCK_EVENT=true`, the proxy duplicated the first real `block` SSE frame. For that root the recorded counts were:

- one proxy duplication marker;
- one `getBlockV2` request;
- one `Ignoring duplicate block event` log;
- one `Observed post-Gloas block` log.

This verifies that the retained-root check suppresses a sequential duplicate before a second API retrieval or evaluation.

### Shutdown

In the connected case, `SIGTERM` produced the normal graceful-stop message and `Closed stream for block events`, after which the Builder process exited.

For the reconnecting case, the recording proxy was stopped after the stream and successful observations had been established. The Builder reported the closed event stream and failed transient API requests. `SIGTERM` then produced the same graceful-stop and stream-close messages, and the process exited without waiting for the proxy to return.

The Builder was run as a host process and was not configured for automatic restart. The EL, BN, and VC remained managed by Kurtosis until each enclave was deliberately removed.

## Harness findings

- The proxy must forward POST bodies because Builder identity and status use `POST /eth/v1/beacon/states/head/builders`.
- The proxy must close active connections on shutdown so the SSE client enters its reconnect path rather than retaining the existing upstream socket.
- The generated network config must be downloaded after every clean launch because its genesis timestamp changes.
- `LODESTAR_PRESET=minimal` must be set for the host Builder to match the fixture preset.

These findings are reflected in the stored proxy and runbook. No Lodestar source change was required by the environment run.
